# 本地 AR 稳定性优化记录

## 已实施的运行时优化

- 首次目标确认：250 ms 调整为 200 ms，在保留瞬时误触发过滤的同时缩短可感知等待。
- 丢失宽限：800 ms 调整为 1000 ms，降低手抖、轻微遮挡和自动对焦造成的模型闪烁。
- 快速重捕获：目标完全丢失后的 2.5 秒内重新出现时，使用 100 ms 确认延迟。
- 资源进度更新：进度变化达到 5% 才跨层更新，减少启动阶段高频 `setData`。
- 模型手势更新：旋转和缩放按 32 ms 合并更新，降低 JS 与渲染层通信压力。
- 本地诊断：控制台输出场景、资源、相机、首次跟踪和稳定结果的相对耗时，不上传数据。
- 生命周期隔离：页面隐藏或卸载后忽略迟到的 XR 资源、相机和跟踪事件，避免旧场景重新创建状态。

## 当前目标图静态质量

| 目标 | 分辨率 | 黑线占比 | 内容覆盖 | SIFT 特征点 | 6×6 特征网格 |
| --- | ---: | ---: | ---: | ---: | ---: |
| part_0001 | 1080×774 | 3.1% | 81.7% | 247 | 26/36 |
| part_0002 | 936×1066 | 10.7% | 90.8% | 1741 | 33/36 |
| part_0003 | 838×1244 | 10.0% | 81.2% | 2045 | 32/36 |

`part_0001` 的线条占比和局部特征数量明显低于另外两张，是真机远距离、运动模糊或
弱光条件下的优先观察对象。正式目标图暂未修改，避免未经真机验证改变模型锚点与比例。

已在 `experiments/ar_target_quality/` 生成独立候选图：黑线占比提升到5.8%，SIFT
特征点提升到1467，特征网格提升到30/36。候选图与旧原图的传统几何兼容验证未通过，
所以只用于“候选图入库并扫描同一候选图”的真机 A/B 测试。当前配置已临时启用候选图，
正式原图仍作为 `originalMarkerSrc` 保留，可一行配置回退。

可重复执行：

```powershell
conda run -n math python tools\analyze_ar_targets.py
```

## 真机验收矩阵

每张目标图至少测试正视、左右 30°、上下 20°、弱光、短暂遮挡和快速移开再返回；记录
`[AR performance]` 与 `[AR tracking]` 日志。建议在一台中低端 Android 和一台 iPhone
上分别执行，每种场景连续测试 10 次，再决定是否调整目标图本身。
